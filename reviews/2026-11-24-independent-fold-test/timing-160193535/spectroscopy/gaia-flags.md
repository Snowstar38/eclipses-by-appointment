# Gaia DR3 SB2 flag and reliability: TIC 160193535

The ESA Gaia archive row for Gaia DR3 1727862804856539264 has `nss_solution_type=SB2`, `flags=8388608`, `goodness_of_fit=15.399521`, `conf_spectro_period=0.99`, and 19 of 19 RVs used for each component. The direct archive CSV, including query provenance and fitted elements, is [gaia_nss.csv](../gaia/gaia_nss.csv).

`8388608 = 2^23`: the only set bit is **TREND_SOLUTION_NOT_APPLIED**. Gaia's [NSS table documentation](https://gea.esac.esa.int/archive/documentation/GDR3/Gaia_archive/chap_datamodel/sec_dm_non--single_stars_tables/ssec_dm_nss_two_body_orbit.html) explicitly describes this as trend analysis not applied in the case of an unsorted SB2. It does **not** mean a trend was detected, nor by itself that the orbital solution is rejected. Bit 26 (`FORTUITOUS_SB2`), which denotes apparently uncorrelated component velocities, is not set; this alone does not prove the solution is correct. No other quality-flag bits are set.

The same documentation defines goodness-of-fit as the Gaussianized chi-square F2, expected approximately standard normal for good fits; 15.4 is therefore a strong warning that the model and assumed errors fit poorly. It does not identify the cause or establish which period is correct. `conf_spectro_period` concerns period detection against Gaussian white noise; 0.99 is not a 99% probability that the period is the unique physically correct period, especially with a poor fit and alias or systematics possibilities. The 19 paired measurements are counts, not published velocities. The formal period error does not capture all such model and alias uncertainty. Gaia's [spectroscopic processing paper](https://doi.org/10.1051/0004-6361/202450600) discusses pipeline and reliability; its SB1-specific selection thresholds should not be transferred uncritically to this SB2.

For direct availability, ESA TAP `SELECT COUNT(*) AS n FROM gaiadr3.vari_epoch_radial_velocity WHERE source_id=1727862804856539264` returned 0; the equivalent query for `gaiafpr.vari_epoch_radial_velocity` also returned 0 (2026-11-24). Those are limited variability releases, not a universal test of every conceivable archive product. Gaia DR3 [documentation](https://gea.esac.esa.int/archive/documentation/GDR3/) describes this epoch-RV table as covering a subset of variables; the [Gaia Focused Product Release paper](https://doi.org/10.1051/0004-6361/202347287) describes the LPV epoch-RV release. Thus no individual component epoch RV series was found for this source in these tables; the orbit cannot be independently refitted from those published rows here.

The TESS deep-event phase mismatch at the published period is documented separately in [summary.txt](../gaia/summary.txt). Together these findings motivate independent time-resolved spectroscopy and pixel-level source attribution; the flag itself does not settle whether Gaia's spectroscopic binary and the eclipsing source are the same system.
