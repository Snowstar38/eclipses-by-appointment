# Independent helper audit — visual10

Scope: independent inspection of the listed cached raw-window figures and new TESScut pixel extraction, not a separate observing occasion. The lead owns the final dispositions. Target identifiers and sky coordinates come from `queue.csv`; the lead's `lead-source-receipts.json` records hashes for the cached SAP inputs. New cutouts are fetched from public MAST TESScut; request URLs, times, sectors, and SHA-256 are in `helper-cut-receipts.json`. Reproduce with `helper-fetch.py` then `helper-pixels.py`; numerical output in `helper-pixels.json`, maps in each target's `helper-pixels.png` (all four inspected). Quality zero; individual event median core and local two-sided baselines, then median difference image. Centroids use positive deficits within 2.5 px of the maximum: approximate diagnostic, not calibrated uncertainties or PSF fits. WCS comes from FITS aperture extension; 21 arcsec/px is only an approximate scale.

X001, X002, X010 have spatially displaced losses strongly supporting off-target variability; no specific contaminating source identified. X004 loss is centered near target at TESS resolution; this does not resolve a close blend. In each row the denominator is the uncorrected target-centered 1.6 px aperture baseline, and the numerator the same aperture's difference flux. These are blended aperture fractions, **not** intrinsic eclipsing-source depths and not a contaminant feasibility test. Individual pixels and sideband/window selections are recorded in code and output. See the maps and event-center lists for the scope; no statistical centroid error is claimed.

Short-clock sanity check, using selected minima already recorded in `lead-clocks.json`, ordinary linear fit to consecutive local cycles: X004 first six S64 events give 3.1913929 d (first fitted center BTJD 3043.225804); the two X002 S88 branches give 7.080793 and 7.085169 d, respectively, roughly 2.87/4.21 d alternating intervals. X001 S61 ~1.43 d and X010 S81 ~0.78 d as in the lead's initial local assessment. These are exploratory local descriptions, not precise orbital periods, multi-season ephemerides or proof of a stellar association. X004's short local cycle does not itself establish the origin of a separate 58.98 d signal.

Gaia neighbor query limitation: ESA TAP returned HTTP 503 for all four; `helper-neighbour-receipts.json` records the attempts. Harvard VizieR returned HTTP 200 but an empty `#RESOURCE=` for the attempted Gaia table (see `helper-gaia-receipts.json` and `helper-gaia.tsv`); this is a failed catalogue query, not zero neighbors. Intrinsic depth and close-neighbor exclusion therefore remain unknown. Successful alternate catalogue and PSF-based contamination budget are next checks. Treating an unobserved window as a null or the same photons reduced differently as a new event would be wrong.

Independent visual audit of lead's `ranked-windows.png`: X005 and X006 troughs are embedded in smooth changing waves, and X009 minima amid rapid oscillations; these selected shapes do not establish repeated detached eclipses. X008 S39 has a credible depression interrupted on egress by a gap; S104's flagged feature is an asymmetric ramp into a gap with subsequent recovery, and S103 is a gap-associated step. Thus the later features are not secure repeats; S39 can remain a singleton for follow-up. X007 S44 and S45 show convincing long flat-bottomed losses; the S46 2560.17 feature is shallower and sits on a changing baseline, so it should not be silently counted as another same-kind deep event. Lead identifies a separate S46 partial primary at the sector end and retains the Gaia-timing tension. These are visual checks of the same data, not independent photons.
